# Playable island generation in the existing game

Continuation of the approved existing-game-mobile-islands specification. Owner now explicitly requests actual generation and both Site/native delivery. The first native checkpoint did not enable islands; this batch must enable a real island for newly started adventures and verify it in the current game. No engine/art/camera/editor replacement.

## Shared interface

- Add `src/islands/scene.js` with pure `tileAt(scene,x,y)` and `sampleScene(scene,x,y)`. Legacy scenes continue reading their unchanged tiles/materials. A compact island scene has `scene.island` containing the existing serializable terrain descriptor, no full `tiles`/material grids, `outdoor:true`, finite canonical props/encounters/arrivals/spawns/routes/landmarks and gen.planVersion4. `tileAt` returns floor on dry land, water on in-bounds sea, void outside. Terrain colors from the smooth sampler are appearance only; mountains remain walkable.
- Add `src/worldgen/world-v4.js`: reproducible one-island plan, scene id `island`, sizes small600/medium800/large1000 and seeded auto600..1000. Additive version dispatch; v1-v3 remain frozen. Core GEN_VERSION stays3 during worker implementation; root switches NEW GAME creation to4 only after integration verifies. Plan must not allocate complete grids. Protect required paths and spawn/access cells from solid props. Use current NPC/model/prop definitions and meaningful places rather than labyrinths.
- Export shared island helpers through the WorldGen bundle (root handles builds). `dist/world.js` uses `window.WorldGen.tileAt` for compact island scenes. Renderer imports the same pure module. Both server and LocalAPI validate hero/enemy/drop collision through it, not `if(scene.tiles)`.
- Current snapshot remains sole hero authority. Canonical v4 environmental changes use existing scene-keyed permanent loot/door/gen flags; defeated encounters and island story progress receive validated monotonic fields, never resurrected on reload. New sparse stores and ship transactions remain a separate next stage, per existing island transaction plan. Do not invent free portals to a new island or expose unfinished travel.
