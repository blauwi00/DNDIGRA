# DNDIGRA на iOS

Существующая игра «За гранью» упаковывается Capacitor 8.5.3: текущие персонажи, пиксельные материалы, полный редактор внешности, инвентарь и правила D&D остаются в том же проекте. Three.js, интерфейс, шрифты и изображения находятся в приложении и исполняются в WKWebView. Сеть для одиночного приключения не требуется. Исходный браузерный режим продолжает использовать серверный API.

`capacitor.config.json` использует `dist/client`, без `server.url` и загрузки опубликованного сайта. Bundle ID остаётся `com.dndigra.game`; стандартные нативные origin/scheme Capacitor сохранены. Не меняйте их между обновлениями: от них зависит доступ к прежнему локальному хранилищу. Текущее требование владельца от 2026-10-12 — альбомная ориентация на iPhone, iPad и Android; оно заменяет старые указания о вертикальном экране. Полная спецификация — [existing-game-mobile-islands](superpowers/specs/2026-10-12-existing-game-mobile-islands.md), Android-инструкция — [ANDROID.md](ANDROID.md).

## Локальный прототип

Требуется Node.js 24. Зависимости Capacitor Core, iOS и CLI зафиксированы на одной версии.

```bash
npm ci
npm run build
npm run test:local
```

На обычном статическом сервере откройте `/?offline=1`: это явный режим проверки локального API. Без параметра `offline=1` браузер работает с прежним сервером. В iOS локальный режим включается автоматически через `Capacitor.isNativePlatform()`.

Герои, выбранная внешность, миры, версии генератора и ревизии сохраняются в IndexedDB. Запись прогресса и проверка ревизии выполняются одной транзакцией; конфликт не перезаписывает более новое сохранение. Отметка завершённого обучения хранится отдельно от миров и сохраняется после их удаления. Ошибка хранилища возвращает ошибку сохранения, а не переключает игру на внешний API.

Локальный API использует те же чистые правила создания героя, генерации мира и проверки снимков, что и сервер. Он не отправляет доверенный заголовок Sites и не выдаёт локального игрока за серверного пользователя. Серверные сохранения остаются в браузерном аккаунте; автоматический импорт в приложение сейчас не реализован. Существующие локальные миры v1/v2/v3 читаются без смены зерна или версии. Удаление приложения удаляет и его локальные данные; штатного экспорта/импорта сейчас нет. Для сохранения прогресса обновляйте установленное приложение с прежними Bundle ID, signing team и нативным origin, без предварительного удаления.

## Каркас iOS

Исходный Xcode-проект уже включён в `ios/` и использует Swift Package Manager. При обычном клонировании проекта не нужно выполнять `ios:add`: на Mac достаточно `ios:sync` и `ios:open`, как описано ниже. Только если нативный каркас отсутствует и его нужно создать заново, используйте:

```bash
npm run ios:add
npx cap copy ios
```

`ios/` содержит исходный нативный каркас. Игровые файлы в `ios/App/App/public` создаются командой копирования и не являются отдельным редактируемым исходником. QA-снимки из `qa/` не входят в пакет.

Иконка приложения и экран запуска пока взяты из шаблона Capacitor. Перед выпуском их нужно заменить оформлением игры.

Приложение требует iOS 15.4 или новее: игровой код использует `structuredClone`, `Object.hasOwn` и `Array.at`. Зависимость Capacitor в SPM допускает iOS 15, а все конфигурации приложения заданы на 15.4. На iPhone и iPad разрешены только `LandscapeLeft` и `LandscapeRight`. В `Info.plist` установлено `UIRequiresFullScreen=true`: на iPad приложение требует полный экран, чтобы шаблонные требования многозадачности не мешали ограничению альбомной ориентации. Интерфейс адаптируется к короткому альбомному экрану, сохраняя текущие игровые элементы и оформление.

Идентификаторы героя, мира, практики и выпавших предметов используют `crypto.randomUUID`, если он доступен. Для нативного протокола предусмотрен UUIDv4 из `crypto.getRandomValues`, без зависимости от доступности secure context. Локальные JSON-ответы создаются обычным конструктором `Response`, чтобы не требовать более позднюю статическую функцию `Response.json`.

Для обновления ресурсов:

```bash
npm run ios:copy
npm run native:test
```

`ios:copy` выполняет браузерную сборку, затем копирование. `ios:sync` также обновляет нативные зависимости. Не выполняйте эти команды во время браузерной проверки, которая обслуживает текущие собранные файлы. Сборка и копирование ресурсов на Linux или Windows дают исходный пакет для Mac, а не подписанный IPA.

## Проверка локального режима в Chromium

`tests/native-browser.cjs` проверяет конфигурацию iOS и сравнивает каждый собранный игровой файл с копией в нативном каркасе. Затем создаёт героя через настоящий локальный API, создаёт мир кнопками интерфейса, сохраняет кадр вступления в IndexedDB и продолжает тот же мир после перезагрузки. Проверка требует сохранения внешности, ресурсов и прогресса без сетевых запросов к API или внешним ресурсам.

Перед запуском нужны доступные Playwright и Chromium. При нестандартном расположении задайте `PLAYWRIGHT_MODULE` и `CHROME_EXECUTABLE`.

```bash
npm run ios:copy
node tests/native-browser.cjs
```

Отдельная лёгкая страница этого теста подставляет `Capacitor.isNativePlatform()` для проверки автоматического выбора локального режима без `offline=1`. Это проверка JavaScript-интеграции; она не заменяет настоящий нативный мост, WKWebView и испытания на iPhone.

## Установка на свой iPhone без платной подписки

Для варианта с редким доступом к Windows на работе подготовлен отдельный [маршрут macOS Actions + SideStore](IOS-SIDESTORE.md). Он описывает сборку через Mac runner и дальнейшие шаги установки; его ограничения и статус проверки указаны в инструкции. Ни этот маршрут, ни раздел ниже не означают, что подписанный IPA или установка на iPhone уже проверены.

Для владельца без Mac и платного Apple Developer самый короткий штатный путь — на время получить доступ к совместимому Mac, например одолжить его или арендовать, и использовать бесплатный Apple ID (Apple Account) в Xcode. Нужен Mac, способный запускать [поддерживаемую Capacitor 8 версию Xcode](https://capacitorjs.com/docs/getting-started/environment-setup), и доступ к своему iPhone. Для первого испытания удобнее Mac с физическим USB-подключением телефона. Аренда или удалённый Mac не считаются доступными, пока не подтверждены условия доступа и подключения устройства.

Windows сам по себе не компилирует и не подписывает iOS-приложение. Linux здесь подготавливает исходники и локальные ресурсы; подписанный IPA, установка через Xcode и работа WKWebView требуют отдельной проверки на Mac. Android APK не устанавливается на iPhone.

На Mac откройте исходный проект и выполните:

```bash
npm ci
npm run ios:sync
npm run ios:open
```

В Xcode:

1. Добавьте свой Apple Account в Settings → Accounts и дождитесь разрешения Swift-пакетов проекта.
2. В target `App` откройте Signing & Capabilities, включите Automatically manage signing и выберите свою Personal Team. Сначала сохраните `com.dndigra.game`; если Xcode не может зарегистрировать его для вашей команды, потребуется доступный уникальный Bundle ID. Такое изменение создаёт отдельное приложение и не переносит прежние локальные сохранения.
3. Подключите iPhone, подтвердите доверие Mac, выберите его как Run destination и запустите `App` кнопкой Run. При запросе устройства включите Developer Mode на iOS 16 и новее; при запросе доверия подписи следуйте Settings → General → VPN & Device Management.

По [правилам Apple для Personal Team](https://developer.apple.com/support/compare-memberships/) бесплатная подпись предназначена для испытаний на собственных устройствах: provisioning profile истекает через 7 дней, после чего нужно снова собрать и установить приложение из Xcode. Также действуют ограничения на устройства, число приложений и доступные возможности. Это требует повторного доступа к Mac; не удаляйте приложение перед обновлением, если хотите сохранить прогресс.

## Проверка и последующие способы распространения

На устройстве проверьте запуск в авиарежиме, обе альбомные ориентации, касания и неподвижную камеру при движении, вырез экрана и безопасные отступы, полный редактор внешности и клавиатуру, кнопки рюкзака/экипировки/диалогов, обучение, бой и звук. Создайте героя и мир, дождитесь успешного сохранения, затем проверьте продолжение после сворачивания и принудительного закрытия. Повторная установка из Xcode с прежней подписью и Bundle ID должна быть отдельной проверкой сохранения данных.

Для TestFlight и App Store требуется платное участие в Apple Developer Program, соответствующая подпись и сборка на Mac; бесплатная Personal Team не предоставляет эти способы распространения. Подготовка Archive и публикация не входят в текущую задачу. Отсутствие Mac или подписки не заменяется обещанием подписанного IPA из Linux, Windows или неподтверждённого облачного сервиса.

В текущем Linux-окружении подписанная iOS-сборка, установка на физический iPhone, TestFlight и аппаратная производительность не проверялись. Проверки Chromium и сравнение скопированных ресурсов не подтверждают испытание на WKWebView.
