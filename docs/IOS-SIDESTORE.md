# Проверка существующей DNDIGRA на iPhone без собственного Mac

Этот вариант сохраняет текущую JavaScript/Three.js игру, редактор, модели,
правила и ассеты. Capacitor загружает `dist/client` из приложения в WKWebView;
опубликованный сайт и игровой сервер не нужны. Локальная игра и сохранения
работают без сети; установка и обновление подписи требуют сети.

Маршрут: **Mac в GitHub Actions компилирует неподписанный IPA → Windows один
раз устанавливает SideStore → SideStore подписывает и устанавливает игру на
iPhone бесплатным Apple Account**. Покупать Apple Developer Program для этого
личного теста не требуется. Сборка всё равно выполняется на настоящем macOS с
Xcode; SideStore не компилирует исходники. В этом окружении Mac-сборка,
SideStore, подпись и физический iPhone ещё не проверены.

## Необязательная Mac-сборка

Workflow собирает проверенный код в отдельной ветке GitHub на macOS runner.
Его доступность зависит от разрешений и настроек Actions в репозитории.
Проверки локальных файлов сами по себе не подтверждают успешную Mac-сборку;
для установки нужен IPA из завершившегося задания.

`.github/workflows/ios-test.yml` запускается только вручную через
`workflow_dispatch` либо при push **точно в `ci/ios-test`**. Push в обычные
ветки, `main`, теги и PR эту сборку не запускает. После локального
коммита текущей проверенной игры отдельный push может выглядеть так:

```bash
git push origin HEAD:refs/heads/ci/ios-test
```

Это отдельное внешнее действие, а не команда для обязательного выполнения
при подготовке исходников. Не используйте принудительный push: если удалённая
ветка уже существует и расходится, сначала проверьте её состояние. Этот путь
не требует слияния игры в `main` и не публикует Site или приложение в магазине.

GitHub разрешает `workflow_dispatch` только когда файл workflow присутствует
в ветке по умолчанию. Поэтому кнопка ручного запуска для одного файла в
feature-ветке может быть недоступна; выделенная push-ветка решает именно это
ограничение. Любое последующее обновление `ci/ios-test` запускает новую сборку.

Workflow использует `macos-15`, **Xcode 26.3** по пути
`/Applications/Xcode_26.3.app/Contents/Developer` и Node.js 24. Текущий образ
runner содержит эту версию; его Xcode по умолчанию 16.4 слишком стар для
Capacitor 8. Образы меняются: если указанный путь исчезнет, шаг завершится
ошибкой и потребуется сверить список установленного Xcode. Workflow ставит
зафиксированные зависимости, проверяет локальное хранилище, собирает и
копирует ресурсы через существующий `npm run ios:sync`, затем вызывает helper.

Helper выполняет `xcodebuild` для существующего
`ios/App/App.xcodeproj`, scheme `App`, `Release`, `iphoneos` и
`generic/platform=iOS`. Все операции подписи отключены. Он проверяет
совпадение скопированных ассетов и отсутствие удалённого `server` в конфиге,
создаёт `Payload/App.app` и упаковывает `DNDIGRA-unsigned.ipa` с SHA-256.
Apple Account, пароль, сертификаты, provisioning profile и GitHub Secrets для
этой сборки не требуются. Неподписанный IPA нельзя установить напрямую.

При успешном Mac-задании скачайте artifact `DNDIGRA-unsigned-ios-<commit>`.
GitHub отдаёт ZIP: сначала распакуйте его в приложении «Файлы» и получите
сам **`DNDIGRA-unsigned.ipa`**, который нужно импортировать в SideStore.
Artifact хранится 7 дней; скачанную IPA можно сохранить дольше.

Те же команды на доступном Mac с Xcode 26.3:

```bash
export DEVELOPER_DIR=/Applications/Xcode_26.3.app/Contents/Developer
npm ci
npm run ios:sync
bash scripts/ios-unsigned-build.sh /tmp/dndigra-ios-artifacts/DNDIGRA-unsigned.ipa
```

Helper хранит временные Xcode/SPM файлы вне checkout и удаляет их после
завершения. IPA тоже должна находиться вне checkout. Команда не меняет
игровые исходники и не загружает приложение в Apple.

## Начальная настройка с Windows и кабелем

Ниже описан текущий официальный путь SideStore через **iloader и
LocalDevVPN**, проверенный по документации проекта 2026-10-12.
Следуйте [официальным prerequisites](https://docs.sidestore.io/docs/installation/prerequisites)
и [install guide](https://docs.sidestore.io/docs/installation/install):

1. Нужен Windows 8 или новее; 32-bit Windows и Windows 10 ARM не поддерживаются.
   Установите iTunes и iloader по ссылкам официальной инструкции. SideStore
   рекомендует iTunes непосредственно от Apple; инструкция также допускает
   Microsoft Store и, при проблемах, Apple Devices. Рабочий ПК должен разрешать
   эти установки и USB-подключение iPhone.
2. На iPhone установите **LocalDevVPN из App Store** по ссылке SideStore,
   разрешите его VPN-конфигурацию. iPhone должен иметь код-пароль и Wi-Fi.
3. Подключите iPhone кабелем, разблокируйте его и нажмите «Доверять» компьютеру.
   Откройте iloader, введите свой Apple Account в его локальном интерфейсе,
   выберите устройство и **Install SideStore (Stable)**.
4. На iPhone откройте «Настройки → Основные → VPN и управление устройством»,
   подтвердите доверие Developer App своего Apple Account. На iOS 18+ это
   **Allow & Restart**; следуйте запросу перезапуска. На iOS 16+ включите
   «Конфиденциальность и безопасность → Режим разработчика» и подтвердите
   ещё один перезапуск, если он запрошен.
5. Включите LocalDevVPN, откройте SideStore и войдите тем же Apple Account.
   Сначала обновите **сам SideStore**: `My Apps`, нажмите его счётчик `7 DAYS`.
   Подтвердите создание/замену сертификата, если SideStore предлагает это
   согласно официальной инструкции. Дождитесь успешного обновления перед
   установкой игры.
6. Сохраните полученный `.ipa` в «Файлы». При включённых Wi-Fi и LocalDevVPN
   откройте импорт IPA в `My Apps` SideStore (кнопка `+`) и выберите
   `DNDIGRA-unsigned.ipa`. SideStore должен переподписать её для вашего
   устройства и установить игру. Этот конкретный шаг с DNDIGRA пока не
   проверен; успешная сборка на Mac сама по себе его не доказывает.

Apple Account и пароль вводите только в локальном iloader/SideStore для
авторизации Apple; передавать их агенту, в исходники или GitHub Actions
не нужно. Pairing-файл также остаётся у вас и не входит в репозиторий.

## Продление, ограничения и сохранения

У бесплатной подписи срок **7 дней**. До истечения обновляйте **SideStore и
игру** на iPhone, подключённом к **Wi-Fi и LocalDevVPN**: в `My Apps` нажмите
счётчик дней или `Refresh All`. Автоматическое фоновое обновление возможно,
но проверяйте срок вручную. Мобильного интернета без Wi-Fi для этого пути
недостаточно. Играть после успешной установки можно в авиарежиме.

Бесплатный Apple Account допускает **3 одновременно установленных приложения
с такой подписью, включая SideStore**; для игры остаётся один из двух свободных
слотов. LocalDevVPN из App Store этот лимит sideload-приложений не занимает.
Также действуют ограничения App IDs (10 в неделю). Платная программа не
потребуется, если оставаться в пределах бесплатных ограничений и продлевать
подпись; TestFlight/App Store этим способом не становятся доступны.

Если SideStore успеет истечь или его pairing-файл потеряет актуальность,
Windows может понадобиться снова. Pairing иногда истекает после обновления
или сброса iPhone и даже без них. Официальная
[инструкция восстановления pairing](https://docs.sidestore.io/docs/advanced/pairing-file):
подключить устройство к iloader, `Delete Stored Pairing`, снова доверить
компьютеру, `Manage Pairing File`, затем `Place` напротив SideStore.
Поэтому обещать «компьютер больше никогда не нужен» нельзя.

Обновляйте игру поверх установленной, тем же Apple Account и устойчивым
bundle/app ID; **не удаляйте приложение ради обновления**. IndexedDB находится
в контейнере приложения. Удаление игры удаляет локальные сохранения;
автоматического импорта сохранений опубликованного сайта сейчас нет.
Первое испытание должно проверить обновление подписи без потери героя и мира.

## Что проверено, а что предстоит

Локально доступные проверки:

```bash
bash -n scripts/ios-unsigned-build.sh
node --test scripts/ios-unsigned-build.test.mjs
```

Тест helper использует **подставной Xcode**: проверяет device/unsigned параметры,
структуру ZIP `Payload/App.app`, сохранение файлов, отказ при устаревших
ассетах/удалённом server и отсутствие IPA при ошибке сборки. Это не компиляция
Swift/SPM, не тест нативного моста и не испытание iPhone.

Предстоят реальное Mac-задание, разрешение SPM, проверка скомпилированной IPA,
подпись/импорт SideStore, landscape и безопасные области iPhone 15 Pro,
редактор с клавиатурой, звук, касания/камера, запуск в авиарежиме и сохранение
после сворачивания, принудительного закрытия и обновления подписи. Доступность
драйверов/iloader на конкретном Windows-ПК тоже ещё не проверена.
