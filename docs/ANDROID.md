# DNDIGRA на Android

Capacitor 8.5.3 упаковывает существующую игру «За гранью»: текущие персонажи, пиксельные материалы, полный редактор внешности, инвентарь и правила D&D остаются в том же проекте. Three.js, интерфейс, шрифты и изображения включены в APK и работают в Android WebView. Для одиночной игры сеть не требуется; браузерный режим продолжает использовать прежний серверный API.

`capacitor.config.json` использует `dist/client`, без `server.url`. Идентификатор приложения остаётся `com.dndigra.game`; стандартные нативные origin/scheme Capacitor сохранены. Их изменение может сделать прежнее локальное хранилище недоступным. Текущее требование владельца от 2026-10-12 — альбомная ориентация на Android, iPhone и iPad; оно заменяет старые указания о вертикальном экране. Полная спецификация — [existing-game-mobile-islands](superpowers/specs/2026-10-12-existing-game-mobile-islands.md).

В `AndroidManifest.xml` задано `screenOrientation="sensorLandscape"`, разрешающее обе альбомные ориентации, и `appCategory="game"`. Категория игры нужна, чтобы Android 16 / API 36 на больших экранах учитывал это ограничение ориентации: игры входят в [официальное исключение](https://developer.android.com/about/versions/16/behavior-changes-16#exceptions) из новых правил изменения ориентации и размеров окна.

## Подготовка сборки

Требуются Node.js 24, именно полный JDK 21 и Android SDK 36 с Build Tools 36.0.0: скрипт проверяет `java` и компилятор `javac` версии 21 перед сборкой. Одного JRE с `java -version` недостаточно; `JAVA_HOME` должен указывать на полный JDK. Установите SDK Command-line Tools, `platforms;android-36`, `build-tools;36.0.0` и `platform-tools`, затем примите лицензии SDK. Для графической работы можно использовать Android Studio. Минимальная версия устройства в каркасе Capacitor — Android 7.0 / API 24; на телефоне также нужен рабочий современный Android System WebView.

Используйте Gradle wrapper из `android/`, а не отдельную глобальную установку Gradle. SDK, JDK, кэши, ключ подписи и готовые APK храните вне checkout и исходного ZIP. Первый запуск требует сети для загрузки npm/Gradle-зависимостей; это не означает сетевую зависимость установленной игры.

Пример переменных для bash; замените пути на свои:

```bash
export JAVA_HOME="/path/to/jdk-21"
export ANDROID_HOME="/path/to/android-sdk"
export DNDIGRA_NATIVE_WORKDIR="/path/to/dndigra-native-work"
export DNDIGRA_APK_OUTPUT_DIR="/path/to/dndigra-apk"
```

Вместо `ANDROID_HOME` можно задать `ANDROID_SDK_ROOT`. Если заданы обе переменные, они должны указывать на один SDK. `DNDIGRA_NATIVE_WORKDIR` задаёт внешнее рабочее место для нативной сборки и кэшей; по умолчанию это `dndigra-native-work` в системной временной папке. `DNDIGRA_APK_OUTPUT_DIR` задаёт внешнюю папку готового `dndigra-debug.apk`; по умолчанию это `artifacts/` внутри рабочего места. Для повторяемых обновлений лучше явно выбрать постоянное внешнее рабочее место, которое не очистится вместе с временными файлами.

Ключ по умолчанию хранится в `<workdir>/keys/android-debug.keystore`, то есть при стандартном рабочем месте — в `os.tmpdir()/dndigra-native-work/keys/android-debug.keystore`. Если файл отсутствует, скрипт создаёт стандартный debug-ключ. Для существующего стандартного debug-ключа обновлений можно дополнительно задать `DNDIGRA_DEBUG_KEYSTORE` с путём к нему. Сохраните этот ключ: обновление уже установленного приложения требует прежней подписи. Скрипт предусматривает Windows-команды `gradlew.bat` и инструменты SDK, но его запуск на Windows ещё не проверен. В PowerShell эти же переменные задаются через `$env:ИМЯ = "путь"`; примеры выше используют bash.

В корпоративной или облачной среде сохраните предоставленные настройки proxy и доверенных CA для npm, Java/Gradle и SDK. Не отключайте проверку TLS и не включайте адреса с учётными данными, сертификаты или ключи в исходный архив.

## Локальный APK

Нативный каркас находится в `android/`; повторно создавать его при обычном клонировании не нужно.

```bash
npm ci
npm run android:sync
npm run native:test
npm run android:build
```

`android:sync` сначала собирает игру, затем выполняет `cap sync android`. `android:build` запускает `scripts/android-build.mjs` и использует уже собранные и синхронизированные локальные ресурсы; он не запускает браузерную сборку повторно. Перед Gradle скрипт проверяет побайтовое совпадение ресурсов и отклоняет отсутствующие или устаревшие копии. После изменения игрового кода снова выполните `android:sync` перед `android:build`. Не пересобирайте `dist/client` во время браузерных проверок, которые обслуживают эти файлы.

Для предварительной проверки инструментов, путей и совпадения скопированных ресурсов без сборки APK выполните `npm run android:build -- --check`.

Другие команды:

| Команда | Назначение |
| --- | --- |
| `npm run android:copy` | Собрать игру и скопировать ресурсы через `cap copy android`; подходит для изменений только веб-кода. |
| `npm run android:sync` | Собрать игру, скопировать ресурсы и обновить нативные зависимости. |
| `npm run android:open` | Открыть существующий проект в Android Studio. |
| `npm run android:add` | Создать каркас через `cap add android` только если `android/` отсутствует; предварительно выполните `npm run build`. |
| `npm run native:test` | Проверить нативную конфигурацию без запуска телефона. |

Игровые файлы в `android/app/src/main/assets/public` создаются копированием и не редактируются отдельно. Debug APK предназначен для локальных испытаний; эта инструкция не публикует игру в Google Play или Sites.

## Установка на телефон

Самый короткий путь — передать готовый APK на Android-телефон, открыть его в файловом менеджере и разрешить установку приложений для этого источника по запросу системы. После установки запускайте DNDIGRA как обычное приложение. APK не устанавливается на iPhone.

При доступном компьютере с Android `platform-tools` можно использовать USB: включите режим разработчика и USB debugging на телефоне, подключите его и подтвердите доверие компьютеру.

```bash
adb devices
adb install -r /path/to/dndigra-debug.apk
```

Замените путь на фактическое имя APK из папки вывода. Флаг `-r` обновляет приложение с сохранением данных, если package ID и ключ подписи совпадают. При ошибке несовпадения подписи используйте исходный debug-ключ; удаление приложения для обхода ошибки уничтожает его локальные сохранения.

Герои, внешность, миры, версии генератора, ревизии и прогресс хранятся в IndexedDB внутри приложения. Сохранения браузерного аккаунта автоматически не импортируются. Удаление приложения или очистка его данных удаляет локальный прогресс; штатного экспорта/импорта сейчас нет. Не меняйте package ID и нативный origin/scheme между обновлениями.

## Проверка установленной игры

Проверьте запуск в авиарежиме, альбомный экран, касания карты и контекстные действия, неподвижную камеру во время движения, полный редактор и клавиатуру, доступность кнопок рюкзака/экипировки/диалогов на коротком экране, обучение и бой по текущим правилам. Создайте героя и мир, дождитесь успешного сохранения, сверните приложение, принудительно закройте и откройте снова: внешность, ресурсы и тот же мир должны сохраниться. Затем проверьте обновление APK с тем же ключом без удаления приложения.

Сборка APK и проверки JavaScript/конфигурации не подтверждают работу на физическом Android WebView. Аппаратные испытания, FPS, звук и поведение конкретного телефона должны быть записаны отдельно; эта документация не заявляет, что они уже выполнены.
